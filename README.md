# 쏘플파티룸 운영 대시보드 — 배포 안내

이 폴더는 그대로 GitHub 저장소에 올리면 되는 상태입니다.

```
index.html    대시보드 본체 (단일 파일, 외부 의존 없음)
_headers      검색엔진 색인 차단 · 기본 보안 헤더
robots.txt    크롤러 차단
README.md     이 문서
```

---

## 시작하기 전에 — 이 대시보드의 성격

지금 파일은 **시연용 프로토타입**입니다. 실서비스와 다른 점이 두 가지 있습니다.

**첫째, 로그인이 서버에서 검증되지 않습니다.** 계정과 비밀번호가 HTML 안에 들어 있어 소스 보기로 확인할 수 있습니다. 주소를 아는 사람은 누구나 총괄 관리자로 들어올 수 있으므로, 외부에 공개할 때는 아래 4단계(Cloudflare Access)를 반드시 함께 적용하세요.

**둘째, 데이터가 저장되지 않습니다.** 시드로 만든 가상 데이터가 브라우저 안에서만 살아 있습니다. 한 사람이 등록한 예약이 다른 사람 화면에는 보이지 않고, 새로고침하면 초기 상태로 돌아갑니다. 실제 데이터가 유출될 위험은 없지만, 여러 명이 같이 쓰는 업무 도구로는 아직 쓸 수 없습니다.

실운영으로 넘어가려면 데이터 계층을 D1 API로 교체하고 서버 측 인증을 붙이는 작업이 필요합니다. 화면은 요약 데이터만 읽는 구조라 그대로 재사용됩니다.

## 1. GitHub 저장소 만들기

1. GitHub에서 새 저장소를 생성합니다. **Private로 만들어도 됩니다** — Cloudflare가 권한을 받아 읽어갑니다.
2. 이 폴더의 파일 네 개를 저장소 최상단에 올립니다. 웹에서 `Add file → Upload files`로 끌어다 놓으면 됩니다.
3. 파일 이름은 반드시 `index.html`이어야 루트 주소에서 바로 열립니다.

## 2. Cloudflare Pages에 연결

1. Cloudflare 대시보드 → **Workers & Pages** → **Pages** → `Connect to Git`
2. 방금 만든 저장소를 선택합니다. (처음이라면 GitHub 앱 설치 권한 승인이 한 번 필요합니다.)
3. 빌드 설정:
   - 프레임워크 프리셋: **None**
   - 빌드 명령: **비워 둠**
   - 빌드 출력 디렉터리: **비워 둠** (저장소 루트가 그대로 배포됩니다)
4. `Save and Deploy` → 1분 내에 `프로젝트명.pages.dev` 주소가 발급됩니다. SSL은 자동입니다.

이후에는 main 브랜치에 커밋만 하면 자동으로 다시 배포됩니다. 수정본을 받으면 `index.html`만 교체하세요.

## 3. 도메인 연결 (선택)

Pages 프로젝트 → `Custom domains` → 예: `dash.도메인.co.kr`
도메인이 이미 Cloudflare에 있으면 DNS 레코드가 자동으로 잡힙니다.

## 4. 접근 제한 — 아무나 못 들어오게 (권장)

Cloudflare Access를 앞단에 세웁니다. Free 요금제에서 **50명까지 무료**입니다.

1. Cloudflare 대시보드 → **Zero Trust** 진입 → 팀 이름 지정 → **Free** 요금제 선택
2. `Settings → Authentication → Login methods`에서 **One-time PIN**이 켜져 있는지 확인
   (이메일로 인증 코드를 보내는 방식. 상대방이 별도 계정을 만들 필요가 없습니다.)
3. `Access → Applications → Add an application → Self-hosted`
4. 애플리케이션 도메인에 위에서 받은 주소 입력 (`프로젝트명.pages.dev` 또는 연결한 도메인)
5. 정책 추가: Action `Allow` → Include → **Emails** → 접근을 허용할 이메일 주소를 나열
6. 저장

이제 그 주소에 들어가면 먼저 이메일 인증을 거치고, 통과한 사람만 대시보드 로그인 화면을 보게 됩니다.
